# ADR-014: Вибір бібліотеки UI компонентів

**Статус**: Прийнято  
**Дата**: 2025-08-21  
**Автор**: Стефан Костик  
**Зацікавлені сторони**: Архітектор проекту, Frontend команда, UX команда

---

## Контекст

Система моніторингу та відстеження нагород потребує комплексної бібліотеки UI компонентів, що забезпечує консистентні, доступні та професійно виглядаючі компоненти. Бібліотека повинна безшовно інтегруватися з Angular та підтримувати theming, інтернаціоналізацію та вимоги доступності.

### Передумови
- Потреба в консистентній дизайн системі по всьому додатку
- Вимоги доступності (відповідність WCAG AA)
- Професійний вигляд, підходящий для корпоративних середовищ
- Підтримка тем та кастомізації
- Інтеграція з Angular екосистемою

### Припущення
- Бібліотеки з підтримкою Google забезпечують кращу довгострокову підтримку та інтеграцію
- Принципи Material Design узгоджуються з сучасними корпоративними очікуваннями UI
- Комплексна бібліотека компонентів зменшує час розробки
- Вбудовані функції доступності є важливими для відповідності

## Рішення

**Angular Material** було обрано як бібліотека UI компонентів для Системи моніторингу та відстеження нагород.

- **Бібліотека компонентів**: Angular Material (остання стабільна версія)
- **Дизайн система**: Google Material Design 3
- **Theming**: Користувацька тема на основі Material Design токенів
- **Іконки**: Material Icons з додаванням користувацьких іконок за потребою

### Обґрунтування
- **Підтримка Google**: Офіційна підтримка Google забезпечує довгострокову життєздатність та інтеграцію
- **Функції доступності**: Вбудована відповідність WCAG AA та функції доступності
- **Консистентний дизайн**: Material Design забезпечує цілісний та професійний вигляд
- **Angular інтеграція**: Спеціально створений для Angular з відмінною підтримкою TypeScript
- **Комплексні компоненти**: Широкий спектр компонентів, що покривають більшість корпоративних випадків використання

## Розглянуті альтернативи

### Альтернатива 1: PrimeNG
- **Переваги**: Багатий набір компонентів, обширні функції, хороша документація
- **Недоліки**: Менш Angular-нативний вигляд, додаткове ліцензування для просунутих функцій
- **Причина відхилення**: Angular Material забезпечує кращу інтеграцію екосистеми

### Альтернатива 2: Nebular
- **Переваги**: Eva Design System, хороші можливості тематизації, орієнтованість на Angular
- **Недоліки**: Менша спільнота, менше корпоративного прийняття
- **Причина відхилення**: Нижче прийняття та менша екосистема

### Альтернатива 3: Користувацька бібліотека компонентів
- **Переваги**: Повний контроль над дизайном та функціональністю
- **Недоліки**: Значний час розробки, накладні витрати на обслуговування, відсутність вбудованої доступності
- **Причина відхилення**: Не практично для термінів одного розробника

## Примітки з реалізації

### Технічні вимоги
- **Версія Angular Material**: Остання сумісна з Angular 20+
- **CDK**: Angular Component Development Kit для просунутих поведінок компонентів
- **Анімації**: Angular Animations для Material компонентів
- **Іконки**: Material Icons та користувацькі SVG іконки

### Встановлення та налаштування
```bash
ng add @angular/material
npm install @angular/cdk
npm install @angular/animations
```

### Конфігурація теми
```scss
@use '@angular/material' as mat;

$primary-palette: mat.define-palette(mat.$blue-palette);
$accent-palette: mat.define-palette(mat.$amber-palette);
$warn-palette: mat.define-palette(mat.$red-palette);

$theme: mat.define-light-theme((
  color: (
    primary: $primary-palette,
    accent: $accent-palette,
    warn: $warn-palette,
  )
));

@include mat.all-component-themes($theme);
```

- **Відображення даних**: Table, List, Paginator, Sort
- **Зворотній зв'язок**: Dialog, Snackbar, Progress Bar, Spinner

## Доповнення 2026-10: Бібліотека діаграм

Angular Material не має діаграм. Особистий дашборд (функція 5.1) використовує **ngx-echarts 21 на ECharts 6**:

- **SVG-рендерер**: чіткий друк і масштабування, а кожна позначка є DOM-вузлом, який можуть перевірити тести й аудит.
  ng2-charts малює на canvas, що нічого не дає екранним читачам і розмивається в друці, а його діапазон залежностей
  уже вимагає Angular 22.
- **Bundle**: tree-shaken імпорти з `echarts/core` (стовпчикові й точкові діаграми; компоненти сітки, підказки,
  легенди й aria; SVG-рендерер) завантажуються з лінивим маршрутом `dashboard` (`provideEchartsCore` з динамічним
  імпортом), тож початковий bundle не зростає.
- **Обгортка**: `shared/charts/ChartComponent` додає ARIA-опис, кольори тексту теми, вимикає анімацію за
  `prefers-reduced-motion` і має перемикач «Показати таблицею», що замінює діаграму таблицею з тими самими даними.
- **Кольори**: токени теми `--app-chart-bar` і `--app-chart-band-1..5` (один синій тон, п'ять кроків для кожної
  схеми, перевірені на монотонну світлоту, помітні проміжки між кроками й контраст щонайменше 2:1 до поверхні у
  світлій і темній схемах), які читає `ChartThemeService` і перечитує при зміні колірної схеми. Дев'ять рівнів
  визнання в одному тоні не розрізнити, тому накопичувальні діаграми об'єднують п'ять рівнів нижче за університетський
  в одну смугу; таблиці й діаграма за рівнями зберігають усі дев'ять.

## Доповнення 2026-11-14: піктограми Lucide (функція 9.3)

Material Icons (шрифт-лігатура приблизно з 2 000 гліфів) поступаються лінійним піктограмам **Lucide**
(`lucide-angular`), які пасують до тонких ліній нового вигляду й потрапляють у збірку поодинці:

- `shared/icons/icons.ts` перелічує кожну піктограму застосунку під коротким ім'ям; `<app-icon name="…">` малює її
  як вбудований SVG кольором тексту, розміром `--app-icon-size`. Піктограми поза цим списком у збірку не потрапляють.
- Піктограми декоративні (`aria-hidden`); елемент керування лише з піктограмою має `aria-label`.
- Правило лінтера `no-restricted-imports` блокує `@angular/material/icon`, тож `<mat-icon>` не повертається.
  Компоненти Material лишаються, змінюється тільки вміст піктограм.

| Варіант | Рішення |
|---------|---------|
| Залишити Material Icons (шрифт) | Відхилено: цілий шрифт заради кількох гліфів, заповнений стиль не пасує до нового вигляду |
| Material Symbols (змінний шрифт) | Відхилено: більший шрифт, той самий підхід із лігатурами |
| SVG Lucide, підключені поштучно | **Обрано**: tree-shaking, лінійний стиль, жодного запиту шрифту |

## Доповнення 2026-11-15: рух, компоненти ефектів і кольори діаграм (функція 9.3)

**Рух.** Типовим лишаються CSS та Angular `animate.enter`/`animate.leave`. Пакет `motion` (лише функція `animate`)
покриває те, що CSS робить погано: лічильник, що наростає до числа, почергову появу елементів списку та пружини. Його
обгортає `MotionHelper` у `shared/effects`: за `prefers-reduced-motion: reduce` він одразу ставить кінцевий стан і
зупиняє кожну анімацію через `DestroyRef` компонента-власника. Його імпортують лише ліниві маршрути, тож початковий
бандл не росте.

**Компоненти ефектів.** Шість власних standalone-компонентів замість стороннього набору ефектів: промінь, промінь по
рамці, прожектор (декоративні, `aria-hidden`), стрічка новин, біжучий рядок і друкований текст (їхній текст лишається
доступним для екранних читачів у статичній копії). Вони рухають лише `transform` та `opacity`, беруть кольори з
токенів і стоять нерухомо за зменшеного руху.

**Кольори діаграм.** Один синій тон доповнення 2026-10 поступається темі: `--app-chart-1..8` — категорійні кольори
серій (ECharts `color`, лінії за підрозділами), `--app-chart-bar` дорівнює `--app-chart-1`, а
`--app-chart-band-1..5` лишаються одним тоном на схему (бордо у світлій, ціан у темній) з тими самими перевірками:
монотонна світлота і щонайменше 2:1 до поверхонь (кольори серій щонайменше 3:1). `ChartThemeService` знову читає
їх усі, коли змінюється схема.
